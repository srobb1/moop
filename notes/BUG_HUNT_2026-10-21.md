## 4. Genomic FASTA silently empty (exporter gene/upstream/downstream/exons, Sequence Retrieval)

When a gene's chromosome was not in the genome, or the gene had no coordinates, both tools wrote
nothing and said nothing — an empty file, HTTP 200. Drosophila's genomic export came back empty.

Fix: one rule, `moop_genome_missing_seqnames()` (lib/genomic_regions.php, one pass over the .fai),
and one message builder, `moop_genomic_skip_notes()`. The exporter writes them as `# WARNING:` lines,
Sequence Retrieval as notes. Covers: chromosome not in genome, no coordinates (this also surfaces the
known GeneID coords bug — Nematostella RS_101, Bradyrhizobium), and no exons found.

## 6. Exon mode exported nothing for 6 gene sets

`moopmartGetExonCoords()` skipped every GFF line without `ID=` — exon lines usually have only `Parent=`
(NV2: 0 exons for a 4-exon gene). It also matched the GFF gene ID to the database id exactly, missing
every `gene:`-prefixed GFF. Now uses lib/gff_gene_model.php's rules. Sampled: 3 gene sets with every
exon line ID-less, 3 with some.

Duplication fixed with it: the id rules ("which database id does this GFF record stand for") now live
in ONE function, `moop_gff_db_id_candidates()`; `moop_gff_id_matches()` is built on it. Also handles
bacteria (gene → CDS, no mRNA) and a top-level transcript.

**Left for a decision** — exon mode mixes exon and CDS records in one numbered list
(`exon1, CDS2, exon3…`), numbered by coordinate even on the minus strand (so "exon1" is the 3′-most
exon there). Proposal: exons only (CDS when a gene has no exon lines), numbered 5′→3′.

## 7. "What is a transcript" defined four ways

Measured: Schmidtea_lugubris types all 20,659 transcripts `transcript`; Parastichopus (2,567) and
Petromyzon (49) mix. The organism page said **"0 transcripts"** for S. lugubris.

Fix: lib/feature_types.php — `moop_transcript_types()` + `moop_transcript_type_sql($col)`. All five

20,682. The organism page's summary is cached: version bumped 4→5, so housekeeping rebuilds it
(until then the figure is omitted, not 0).

The GFF rule stays separate on purpose (it decides what to DRAW from a GFF; the list decides what to
COUNT in the DB). The file header says so. If they ever need to agree, make the GFF rule use the list.

### 8b. 🟡 MEASURED: `extractFastaRegion()` re-reads the .fai for every region it cuts

Two .fai readers do the same lookup: `extractFastaRegion()` (blast_functions.php, one seqname per call,
scans from the top every time) and `moop_fai_lookup()` (fasta_index.php, many names in one pass).

Carollia_perspicillata (1,925,339-line .fai; its 23,041 genes sit on lines 2–53,844, mean 22,506):
300 random genes = **1.70 s (5.7 ms/gene)** through `extractFastaRegion()`; ONE `moop_fai_lookup()` for
all 300 scaffolds = **0.006 s**. Projected full gene-set genomic export: **~131 s spent re-reading the
index**. Affects the exporter's genomic modes, Sequence Retrieval and BLAST region fetches.

Proposal: look the batch's seqnames up once (`moop_fai_lookup()`), then cut from the entry — split
`extractFastaRegion()` into lookup + `read region at entry`, and make it a thin wrapper so single-region
callers are unchanged. Not done while the user was away: it changes the shared reader under three tools.
Measure the export end-to-end before and after.
